# Database migrations

Alembic migrations for Network Defender.

The database URL is **not** configured in `alembic.ini`. `env.py` resolves it
from `config/setup.json` and the `DATABASE_URL` environment variable, so there
is one source of truth and no credentials in a tracked file.

## Commands

Run from the repository root:

```bash
uv run alembic upgrade head              # apply all pending migrations
uv run alembic downgrade -1              # revert the most recent migration
uv run alembic current                   # show the applied revision
uv run alembic history --verbose         # list all revisions
uv run alembic revision --autogenerate -m "add x"   # generate from model changes
uv run alembic upgrade head --sql        # emit SQL without applying it
```

The application also applies migrations programmatically on startup via
`network_defender.database.migrations.upgrade_to_head()`.

## Notes

- **Always review autogenerated migrations.** Alembic detects added and dropped
  tables and columns reliably, but renames appear as a drop plus an add, which
  loses data.
- SQLite cannot `ALTER` most columns in place. `env.py` enables batch mode on
  SQLite, which rebuilds the table instead, so migrations behave the same on
  both backends.
